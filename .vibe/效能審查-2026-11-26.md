# 效能審查：茄記 2.1.0（feat/2.1）

> 2026-11-26，多米問「目前的程式碼有沒有性能問題」。只讀程式，沒改、沒編譯、沒在真機量。
> 範圍 `ios-native/`（約 19,000 行）分四區看：存檔與同步（Core、Shared、分享擴充、小工具）、紙面（Paper）、目錄（Dir）、首頁與設定等外圍（App、Design）。
> 下面「確定」的是程式路徑我回原始碼對過；毫秒數除了標「量過」的，都是估的，要真機量才算數。
> 已經知道的不重報：第一次升鍵盤 260–330 毫秒、第一次拿起磚 24＋34 毫秒、第一次按住一行 8–10＋19–28 毫秒、返回鍵不見（4ba5c5d 在修）。

## 一句話

清單本身寫得對，1000 行也不會因為行多而卡。會頓的地方集中在三件事：iCloud 同步完、回到前景時在主執行緒把整本存一次檔並讓整個畫面重畫；首頁一點小事（同步時間、價格、提示條）就讓整張紙重算；目錄點一下或往下拉，所有頁的所有磚都重算。三件都跟資料量成正比，紙越多越明顯。

## 建議先修（影響手感、改法清楚）

### 1. 同步上傳完、回前景：主執行緒整本存檔＋整個畫面重畫　高／確定

- **上傳完**：`Core/CloudLink.swift:224` → `adoptSync`（`:310-328`）只是記下「這張傳過了」，卻用 `replaceBook` 叫整個畫面重畫，再 `flush()`。`flush()` 是 `queue.sync { put(book) }`（`Core/Disk.swift:250`），在主執行緒把整本轉成文字寫檔。
  - 什麼時候：開著同步，打字停手約 2.3 秒（存檔 0.25 秒＋等 2 秒上傳）。人可能正接著打下一個字。
- **回前景、打開 app**：`CloudLink.swift:166` → `Store.mergeCloud`（`:298-307`）在主執行緒解每個 iCloud 檔、合併，不管有沒有變都 `replaceBook`＋`flush()`。拉一下控制中心再放開也算一次。
- **回前景清最近刪除**：`App/QiejiApp.swift:169` → `purgeTrash`（`Core/StoreNotes.swift:112`）用 `edit {}`，沒有過期的東西也會整個畫面重畫、排一次存檔、再排一次上傳。
- 改法：只變同步記號時用 `quietly` 寫、改 `saveSoon()`（背景存）；`mergeCloud` 沒變就直接 return，解檔搬到同步的背景佇列；`purgeTrash` 先在副本上算，有清掉才寫回。
- 風險：動到存檔與同步時機，要對著 `.vibe/安全標準.md` 和存檔保護那批測試（`DiskGuardTests`、`LegacyGuardTests`）跑。`flush()` 留給進背景用，那裡要同步寫是對的。

### 2. 首頁一有動靜，整張紙就重算一次　中～高／確定（毫秒數沒量）

- `App/QiejiApp.swift:45-48` 根畫面看著 `shop`、`look`、`cloud`、`quick`，加上 `store`。`PaperView` 帶著 closure（`:256-259`），SwiftUI 比不出它沒變，根畫面每重畫一次，紙就跟著重算：`PaperList.updateUIView`（`Paper/PaperList.swift:41-62`）把整張紙每一行重新轉一次、整串比對，再重設封面那塊。
- 根畫面其實用不到、卻會觸發的：
  - `cloud.lastSync`：每次上傳成功都設，只有設定頁用得到。跟第 1 條同一刻發生。
  - `shop.priceFailed`：沒買的人打開設定頁或付費頁，`loadPrice()`（`App/Purchases.swift:100`）馬上設一次，價格回來再一次。正好落在推頁動畫裡。
  - 按右下 ＋、提示條出現與 3.5 秒後收起。
- 改法：紙學目錄 `DirHost` 包一層只比紙 id 的 Equatable host；`cloud`、`look`、`shop` 各自拆成只看自己的小 modifier。
- 風險：低，畫面行為不變。

### 3. 目錄：點一下、往下拉，所有頁的所有磚都重算　高／確定

- `Dir/DirTiles.swift:394` 每一頁 `DirPageView` 都看著整個 `DirModel`。頁是一般 `HStack`（`Dir/DirPanel.swift:284`），看不到的頁也在。`DirModel` 任何一個值變了，每頁都重建所有磚的資料、把每塊磚推進 UIKit 比一次（`DirTiles.swift:322-339`）。
- 什麼時候：
  - 點一下磚：按下設 `heldID`、放開清掉（`Dir/DirModel+Touch.swift:131-143`），就是兩次；換紙再一次。之前量到「點了什麼都沒打開也要 8.6–12.6 毫秒」，我判斷大半是這個。
  - 開始左右翻頁也付這兩次。
  - 往下拉把手收目錄：`pull()`（`DirModel+Touch.swift:262-267`）每一格畫面都改 `progress`，等於每格都全部磚重算一次。磚越多越不跟手。
- 改法：按著、彈一下、瞄準疊上去這類只關一塊磚的狀態，改成像 `setCover`（`Dir/DirModel+Folder.swift:42`）那樣直接改那塊磚；`DirPageView` 不看整個 model；拉把手的位移放一個獨立的小物件（同 `DirGhost` 的做法）。
- 驗法：模擬器 `QIEJI_PERF=1`，看一次點擊裡所有頁 `grid` 加起來多少。

## 第二批（有感但範圍小，或要先量）

### 4. 冷啟動把整本算了三次　中／路徑確定、毫秒數沒量
`store.boot()`（`QiejiApp.swift:110`）在主執行緒讀檔解析、每張紙重算指紋、再整本轉文字一次只為了跟原檔比、最後 `flush()`（`Core/StoreNotes.swift:98`）。改 `saveSoon()`、指紋放背景先算。先量冷啟動 `stamp` 那段多久。

### 5. 封面小圖沒在快取時，在主執行緒解整張 1200 寬的 JPEG　中／路徑確定
`Design/TileArt.swift:131` 的 `draw()` 裡叫 `Covers.shared.thumb`，沒命中就當場讀原圖縮圖（`Core/Covers.swift:66-74`）。剛開 app 預熱沒做完就打開目錄或切換清單、記憶體吃緊快取被清、iCloud 剛下載一批封面，都會走這條，一次十幾張就是同一格解十幾張。另外開 app 時預熱是每張封面同時丟一條背景工作（`Covers.swift:82-90`），封面多時一起搶。改法：小圖只在背景做好才放進快取、才叫磚重畫；預熱改成最多兩條同時跑、用 ImageIO 直接解成小圖尺寸。iCloud 封面的讀寫（`CloudLink.swift:267`、`:287-291`）也從主執行緒搬走。

### 6. 搜尋每打一個字算兩次全文　中／確定
`Dir/DirSearch.swift:12` 在畫面裡直接跑 `Seats.searchLines`，每張紙把名字、內文、所有行接成一串再轉小寫（`Core/Seats.swift:38`）。`DirPanel.swift:49` 的 `onChange(query) { page = 0 }` 又讓它多跑一次。另外開始搜尋、清掉搜尋會把整面磚拆掉再全部重建（`DirPanel.swift:269-276`）。改法：`page` 不是 0 才設；結果照 query 快取；格子用藏的、不拆。

### 7. 紙面兩件　中／確定
- ⋯ 選單裡的分享（`Paper/PaperHeader.swift:196`、`:226`）每次紙重畫都先把整張紙組成文字。劃掉一行、打字停手都會跑，1000 行估 1–3 毫秒。要確認的話：千行的紙劃掉一行、不打開 ⋯，看 PerfMeter 有沒有出現組字的時間。改成按下去才組。
- 有封面的清單捲動時，每一格都重畫封面那四塊 SwiftUI（`Paper/LineList.swift:341-344` 每格寫 `spy.y`；`Paper/CoverViews.swift:74` 的 `CoverHead` 看著 `spy` 卻沒用到 `y`）。改 `let spy`、捲過頭之後值不變就不寫。

### 8. 打字時一直叫醒小工具　中／確定
每次存檔成功就 `pushWidget()`（`Core/Store.swift:364`），改的是前 10 行時快照就變，`WidgetCenter.reloadTimelines` 每零點幾秒叫一次。改成換紙、進背景、或停手久一點才推。耗電要真機看。

### 9. 推進來的頁　中低
- 最近刪除（`App/TrashPage.swift:38-41`）每次重畫都過濾排序全部紙、展開全部刪掉的行，又不是 Lazy，30 天內刪很多行時會慢。
- 設定頁推進來時在主執行緒問 iCloud 容器位置（`App/SettingsPage.swift:61` → `Core/Cloud.swift:63-68`），Apple 文件說不要在主執行緒呼叫，第一次可能卡在推頁動畫裡。

## 查過、沒問題的

- 紙面清單只掛畫面附近的行，行會回收重用，高度有快取，打字只重量改到的那一行；1000 行捲動跟行數無關。
- 打字走 `quietly`，每個字不叫畫面重畫，停 0.25 秒才畫一次；輸入框的草稿不會觸發重畫。
- 一般存檔在背景序列佇列做，內容一樣就不寫。
- 拖磚時只有拖著的那塊自己重畫；資料夾放大是預先算好的系統動畫，主執行緒忙也不頓。
- 所有 CADisplayLink（自動捲動、資料夾、甩）動完都會停，沒有計時器殘留，沒找到循環引用。
- 切換清單的列會回收，開收時紙不跟著重畫；目錄收起後不跟著打字做事。
- 分享擴充不載圖片影片、字有截斷，記憶體在擴充的上限內。
- 小工具只讀一小份資料、不自己排更新。
- 震動產生器共用一份、有先準備。

## 建議的順序

1. 先量三個數字：上傳完那次 `flush`、回前景合併加 `flush`、冷啟動。`QIEJI_PERF=1` 只能在模擬器帶（多米沒有 Mac，TestFlight 版帶不了環境變數），先在 limrun 用 -O 編、塞千行大資料量；要真機數字得另外做一個隱藏開關。
2. 第 1 條（同步存檔）和第 2 條（首頁連帶紙重算）一起修：同一刻發生，改法都不動畫面行為。
3. 第 3 條（目錄）單獨一批：改的是目錄的狀態流，要用模擬器錄影對照點擊、翻頁、拉把手的手感沒變。
4. 其他照順手修。

## 第 4 條冷啟動（overnight 2026-11-26）

一句話：打開 app 時主執行緒讀資料那一段，從約 34 毫秒降到約 12 毫秒。資料、存檔格式都沒變。

### 改了什麼

1. **打開時不當場存檔**（`Core/StoreNotes.swift`、`Core/Store.swift` 的 `saveAfterBoot`）。以前讀完存檔，馬上在主執行緒替每張紙算指紋、把整本轉成文字跟原檔比，多半比完發現一樣、什麼都沒寫。現在改成跟打字時一樣：指紋先在背景算，存檔在背景寫，內容沒變照樣不寫。
2. **讀檔解析變便宜**（`Core/JSONValue.swift` 的 `from`、`Core/NoteCoding.swift`、`Core/Disk.swift`）。以前把系統解出來的資料先整包轉成 Swift 的字典、再轉一次成我們的格式；現在直接看系統給的那份，只轉一次。存檔讀進來的位元組也直接解，不先轉成字、再轉回位元組。直接解不出來，照以前的路再解一次，所以讀得進來的檔跟以前一模一樣。

### 什麼時候還是當場寫

只有「讀到自己的存檔、讀得懂」才排到背景。這時記憶體裡跟檔案只差「下次打開會照樣再補一次」的東西：指紋、排列、清掉過期的最近刪除。打開還沒存就被殺掉，下次打開讀到的是同一份檔，補出來的一樣，一個字都不會少。iCloud 一定是存檔成功之後才傳，不會先拿到檔裡沒有的東西。

下面這些照舊當場寫，打開馬上被殺掉也不准丟：

- 第一次從 1.1 搬過來
- 新裝第一次打開（教學紙）
- 存檔讀不出來、原檔另存過
- 讀不到的那段時間記的字，回到前景讀到了要補進去（`thaw`）、或選了「從空的開始」

打開後馬上切到背景：進背景那次 `flush()` 會取消排著的那一趟、當場寫完，跟以前一樣。

存檔保護（`Disk.held`、`Store.frozen`、`LegacyGuard`、`DiskGuard`）一行沒動。

## ＋ 按下去紙重算（overnight 2026-11-26）

一句話：按右下 ＋ 到輸入框升好、鍵盤到位，紙從重算 3 次變 1 次；從手指放開到輸入框開始升，主執行緒從約 7.2 毫秒降到約 4.2 毫秒。整段按一下的總時間只少約 3 毫秒，因為大頭是系統升鍵盤（兩輪各約 33 毫秒），那部分本來就不是紙的。

### 3 次是誰

量測點記下每一輪主迴圈裡發生的事，按一次 ＋ 固定是這三次：

1. ＋ 的數字（`plusAsk`）放在 store 上：一加一，看著 store 的紙和根畫面都先重算一次，什麼都沒變。
2. 輸入框打開（`composing = true`）：紙要變暗、輸入框要升，這次本來就要，留著。
3. 鍵盤升起通知（`KeyboardWatch.up`）：紙整張看著鍵盤，又重算一次；可是輸入框開著時，跟鍵盤有關的兩件事（右上 ✓、右下 ＋）都不會變。

### 改了什麼

- `Core/Store.swift`：＋ 的數字搬到自己一份小物件 `store.plus`（跟 `fab` 一樣），不再是 store 上的 `@Published`。
- `App/QiejiApp.swift`：＋ 按下去改加 `store.plus.asks`。
- `Paper/PaperView.swift`：紙不直接看著 ＋ 的數字和鍵盤，改用第 2 條那個只看一個值的小 modifier（`Watch`）：＋ 的數字變了就照舊叫 `addLine()`；鍵盤升降就照舊叫 `updateFab()`。鍵盤物件還是紙自己的一份，只是不讓它一變就整張紙重算。
- `Paper/PaperHeader.swift`：右上 ✓ 要不要畫（鍵盤開著＋正在行裡、清單名、記事本打字）改在標題列自己算，標題列自己看著鍵盤。鍵盤升降時只重畫標題列，跟以前同一刻、同一段動畫。

輸入框本身（`Composer.swift`）、升起的時機、紙變暗、注音、✓／往下拉／點一行收起，程式一行沒動。
