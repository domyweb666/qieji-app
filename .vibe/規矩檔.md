# 規矩檔（AI 每次動工前必讀）

## 通用 AI 行為基準（從專案第一天起就成立，勿改）

1. **不准猜假設，不確定就問。** 收到任何指令，若有不明確的詞、有多種可能的解讀、缺少關鍵資訊——**停下來把不明確的地方列出來問使用者**，不要替他選一個解讀就動手。靜默的假設是這套系統最大的失敗源頭。

2. **每一行改動都必須能追溯到使用者的明確要求。** 不准順手「改進」相鄰的程式碼、不准重整不相干的格式、不准刪掉「看起來像死碼」但不在這次任務範圍內的東西、不准做沒被要求的重構。每一行 diff 都要對得上一句使用者講過的話。
   - **（刻意反「童子軍原則」，重要）**：工程界有條「童子軍原則／破窗效應」——路過爛 code 順手修乾淨。**這套系統故意不這樣做**：對看不懂程式碼的人，「順手清理」是**驗不到的暗改**，一個 drive-by「整理」可能靜默弄壞別處而他永遠看不到。所以**破窗要修，但要用一片正式的 `vibe-simplify`（走過審核）去修，不准路過時即興順手改**。清理是一個被切出來、驗得到的動作，不是夾帶在別的任務裡的副作用。

3. **不准加沒被要求的功能、抽象、設定項。** 「想說以後可能會用到」「順便寫得更彈性一點」「加個 config 比較好」——全部不准。要做的事跟使用者要的事一對一，多的一律砍。（注意：這條禁的是替想像情況**鍍金**；下面第 4 條的健壯性地板是**最低要求**，不在此限。）

4. **錯誤要大聲、輸入要驗、爆了要倒向安全側（健壯性地板）。** AI 寫的程式表面會跑，但**邊界與錯誤處理常常是空的**——而看不懂程式碼的人看不到空的 catch、看不到沒驗證的輸入。這四條是地板，寫任何程式一律遵守（這不是第 3 條禁的「鍍金」：錯誤一定會發生，差別只在「大聲報」還是「默默吞」）：
   - **快速失敗、不准默默吞**：一發現不對就大聲報錯停下，**不准用空的 catch 把錯誤吃掉繼續跑**。吞掉的錯不會消失，只會用更難懂的形式在更遠的地方爆。
   - **外部進來的一律先驗證**：使用者輸入、API 回傳、檔案內容——用之前先檢查，絕不假設它是好的（這同時是健壯性與安全的根）。
   - **爆掉時倒向「拒絕／鎖住」，不是「放行」**：尤其權限／付費／安全相關，出錯的預設是「不准」，不是「那就讓他過吧」。
   - **保護式子句**：不合法的狀況在函式開頭就擋掉提早 return，讓正常路徑保持平坦，不要把主邏輯埋在層層巢狀 if 裡。

## 專案特定規矩（vibe-voice-lock 之後寫入這下面）

### 手感是最高標準（2026-11-04 多米定，蓋過其他取捨）

多米原話：「我的最高要求就是體感要好，不管是編輯還是操控的體感都要提升到極致。畫面不准有不順暢感，我的唯一標準就是極致的手感體驗。」

判斷順序：手感 > 功能多寡 > 程式好不好寫。畫面不順算 bug，不算「之後再優化」。之前的定案、架構只要擋到手感，都可以提出推翻（講清楚會動到什麼）。

動工時的底線，七條都過才算做完：

1. **結果當下就發生，動畫只是過場。** 不准「等動畫跑完才做事」：點了換紙就馬上換，面板自己收。動畫完成的回呼只能拿來收尾（卸載、歸零），不准放使用者要的結果。
2. **手指碰到，同一格畫面就要有反應。** 跟著手指的東西（拖、滑、捲）全部在 UI 執行緒算，不准等 JS。要回 JS 的只有一次性的事（存資料、開選單）。
3. **不准閃、不准跳。** 同一個東西的位置不准由兩套機制分開改（版面重排一次、動畫位移一次），兩套落在不同格就會閃。要嘛全在 UI 執行緒同一格改完，要嘛只留一套。
4. **花費不准跟資料量成正比。** 打開、換張、捲動、拖曳的成本，一千行跟十行要差不多：只掛畫面附近的行，每行只放畫得出來的東西（字），輸入框、手勢能共用就共用、能晚建就晚建。
5. **一次動作只准重畫一次。** 卸載時順手 `store.change()`、換紙時順手寫存檔這類「多跑一趟」都算手感 bug；存檔、推小工具、同步一律排到動畫之後。
6. **有量才算數。** 動到手感先看 `[perf]`（`lib/perf.ts`，印在跑 tunnel 的終端機），改完貼前後對照；沒量到的瓶頸不准憑感覺調。開發版比正式版慢好幾倍，要分得清是真的慢還是開發版慢：感覺要用 `npx expo start --tunnel --no-dev --minify`（正式版的 JS）或 Release 建置看。
7. **手感好不好只有多米真機說了算。** AI 不准自評「應該順了」；網頁預覽只能驗邏輯，驗不了手感。做完給可以照條號回報的待驗清單。

## 踩過的坑・不准再犯（vibe-no-repeat-error 自動回灌）

- 2026-10-31｜**正在打字的輸入框附近不准用 `pointerEvents='none'`。** 為了「點一下不進編輯」把沒在編輯的行包成 `pointerEvents='none'`，切到下一行時舊的那行被關掉，鍵盤收了再開。RN 在 iOS 上把它做成整塊 `userInteractionEnabled = NO`，第一回應者會被迫放掉。要擋點擊就蓋一層看不見的 View 在上面；鍵盤相關的改動網頁測不到，一定真機。

- 2026-10-31｜**`onKeyPress` 裡接手 Backspace 並把焦點移到別的輸入框，一定要 `e.preventDefault()`。** 行首 Backspace 併到上一行時，網頁預覽多吃掉接點前一個字：瀏覽器的預設刪字在 handler 之後才跑，那時焦點已經在上一行、游標在接點。iOS 是原生先刪、JS 後到，看不出來；但只要 handler 會移焦點就擋掉預設動作，兩邊才一致。

- 2026-10-31｜**手勢 worklet 裡不准呼叫一般 JS 函式。** 把劃掉門檻寫成 tokens 裡的函式，在 `usePanGesture` 的 `onDeactivate`（UI 執行緒）呼叫，真機一滑就整個 app 崩潰；網頁預覽同一條執行緒所以測不出來。規則：給 worklet 用的值只能是純數字、字串、shared value；要算就在 worklet 裡自己算。網頁預覽過了不代表手勢沒問題，碰 worklet 的改動一定要真機。

- 2026-11-02｜**借 iOS 系統 App 的互動（主畫面編輯、檔案夾、拖放）之前，先找 Apple 官方原文（iPhone 使用手冊＋HIG）列成對照表，不准憑印象做。** 目錄和資料夾照印象做，漏了「按住空白處進晃動」「晃動中點檔案夾會打開」，還多加了 iOS 沒有的「移出資料夾」文字選單，多米真機才抓到。對照表在 `.uiux/iOS主畫面編輯-官方規範對照.md`；跟官方對不上的地方先問多米，不自己決定。多米偏好：能用手勢直接做的，不要另外做文字選單（VoiceOver 動作照留）。

- 2026-11-02｜**動畫的 worklet（useAnimatedStyle、手勢的 onUpdate 等）裡只准用 shared value 和拆出來的數字／真假值，不准寫 `p.xxx`、不准碰紙、資料夾物件。** 目錄磚的動畫寫了 `p.ghost`，把整包 props（裡面有紙、資料夾物件）抓進 worklet，Reanimated 把那些物件鎖住：之後改資料（拿出資料夾、刪行、打勾）有的不生效、有的直接報錯，多米真機「一團糟」，還讓「移出資料夾沒移出」查了兩輪才找到。要用就先 `const ghost = p.ghost;` 再在 worklet 裡用 `ghost`。終端機出現 `[Worklets] Tried to modify key` 或 `Cannot copy value of type FiberNode` 就是這個問題。

- 2026-11-02｜**模仿常見平台的互動（主畫面、資料夾、拖放），先把整套規格列出來、一次跟多米對完，不准做一點補一點。** 這次的做法：先做能玩的虛擬手機原型（Artifact）給多米對，他說完美之後拿原型逐項對照茄記（`.uiux/iOS主畫面編輯-官方規範對照.md` 第六節），差異一次列完再改。原型裡修掉的病（拖著經過就讓位，害左右疊不起來），茄記也逐條查一遍。

- 2026-11-03｜**拖曳門檻、長按時間這類手勢設定，網頁預覽過了不算數，iOS 跟網頁的 RNGH 行為不一樣。** 目錄「長按選單一跳就變拖」「抖動中點資料夾變成拖」第一次修只改了 `minDistance`，網頁驗過，真機照壞。原因（讀過 RNGH 原始碼 `apple/Handlers/RNPanHandler.m`）：(1) iOS 的 `activateAfterLongPress` 時間一到拖曳就直接啟動，完全不看 `minDistance`；(2) `activateAfterLongPress: 0` 在 iOS 是「延遲 0 秒、手指一碰就啟動」，網頁的 0 才是「不等長按」。規則：不要的時候給 `undefined`，不准給 0（沒給值的欄位不會傳到 iOS，v3 換設定時 iOS 先全部清回預設）；「長按後要拖多遠才算」在 worklet 的 onUpdate 自己算（`DirPanel.tsx` 的 `useDragPan` armed）。改手勢設定前先讀 `node_modules/react-native-gesture-handler/apple/Handlers/` 對應的檔，確認 iOS 怎麼用這個值。

- 2026-11-03｜**RNGH v3 的手勢（usePanGesture 等）一定要跟接它的 GestureDetector 在同一個元件、同一輩子，不准在 A 元件建、交給一直掛著的 B 元件畫。** 底部列搬到紙外面時手勢還留在紙裡建：第一張紙滑得動，換過一次紙膠囊就滑不動（多米真機）。原因（讀過原始碼）：iOS 的偵測元件 `LeanReanimatedNativeDetector` 掛上時就把事件綁給當時那個手勢的處理器，之後換成別的手勢，Reanimated `NativeEventsManager.updateEvents` 比的是掛上時記下的那份，新的處理器永遠接不上。要跨元件用，就把手勢建在畫偵測元件的那個元件，別的元件只交資料（shared value、id、要排回 JS 的函式）。網頁版偵測元件是另一套，網頁預覽測不出來。

- 2026-11-03｜**同一個拖曳裡的幾個判斷（翻頁、出框、瞄哪一格）要用同一個基準。** 資料夾裡「到框邊翻頁」改成看手指、「出框拿出資料夾」還看磚的中心：抓磚右半邊往左拖，手指到框邊時中心已出框，出框 350 毫秒先於翻頁 600 毫秒，資料夾收起、那張被拿出去（多米真機「跨頁被搬到外面」）。改一個判斷的基準時，把同一個手勢裡其他判斷一起對過。
- 2026-11-03｜**worklet 函式的參數不准寫預設值去用外面的變數（`function slotX(k, cw, cols = COLS)`）。** 目錄改 1×1 時這樣寫，網頁預覽正常，真機一拖磚就閃退「Property 'COLS' doesn't exist」：worklet 只把函式本體裡用到的外面變數帶到 UI 執行緒，參數預設值用到的不帶。規則：參數寫成可選（`cols?: number`），在本體裡 `cols ?? COLS`。
- 2026-11-04｜**手勢進行中會變的狀態，不准拿來切換 `zIndex`（自己、爸爸、兄弟都算）。** 目錄根節點選單開著時加 `zIndex: 1`、關了拿掉：跳出選單後手指不放接著拖，`setMenu(null)` 一關，兄弟順序就變，Fabric 把目錄整塊 Remove＋Insert，底下的 RNGH 偵測元件 `willMoveToWindow:nil` → `detachAllHandlers`，拖到一半的手勢當場取消（記錄 `deactivate canceled=true dx=22`，磚不跟手）。同一天拖把手（被拖那行 `zIndex: 5`）也是這類，模擬器上修前修後紅綠對得上。網頁的 zIndex 是 CSS，不會拆，網頁預覽測不出來。規則：要改上下疊放就固定 JSX 順序，不用 zIndex 開關；非用不可，把會動的包進自己一層（`Paper.tsx` `Rows` 那層）。碰手勢先上雲端模擬器驗（`.vibe/待審-雲端模擬器自動測.md`），手感還是真機。
- 2026-11-04｜**拖曳路上會經過的區域，不准「待滿時間就動作」，要等手停下來。** 目錄往別張正中間拖一定會先經過外圈的互換區，待滿 100 毫秒就互換，底下那張被換走，慢一點的手永遠疊不起來（多米真機「疊資料夾的功能不見了」；模擬器腳本是一步跳到正中間，所以一直測不出來）。要測手勢就用真人的速度分段跑（50～800 點／秒），不准用跳的。修法見 `DirPanel.tsx` 的 `whenStill`、`gesture.swapStill`。
- 2026-11-04｜**從沒有標題列的頁面（紙）推進去的頁面，不准開系統大標題。** 最近刪除開 `headerLargeTitleEnabled`，標題列邊進場邊長高，標題往下掉約 25 點，內容沒動，多米真機「詭異的抖動」。第一次憑感覺猜成樣式晚套用，修了沒用；錄影逐格才看到。規則：動畫的問題先錄影逐格看，不准先猜。頁名畫在內容裡（`trash.tsx`）。
