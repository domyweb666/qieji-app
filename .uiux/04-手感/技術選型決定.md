## 一、可行路線（怎麼裝到真機）

| 路線 | 要什麼 | 限制 | 查證 |
|---|---|---|---|
| **Expo Go**（目前在用） | iPhone 裝 Expo Go；Windows 跑 `npx expo start`，掃 QR code | 專案的 Expo SDK（目前 58）要跟 App Store 上的 Expo Go 版本對得上；只能用 Expo Go 內建的原生套件（`react-native-webview` 在內） | [Expo：work without a Mac](https://docs.expo.dev/preview/simulators/how-to/work-without-a-mac.md)、[Expo blog](https://expo.dev/blog/build-ios-apps-on-windows-with-cloud-simulators)，2026-10-31 查。**SDK 58 對應哪版 Expo Go 沒查到，開之前先在手機上確認** |
| EAS Build 開發版 | Apple 付費開發者帳號；在 Expo 的雲端 Mac 編譯 | 要付費帳號才能裝到 iPhone | 同上 |
| 模擬器 | — | **不算數**：沒有觸覺、沒有手指遮擋、延遲不同（3-4） | — |

目前用 Expo Go 就夠了，兩個候選都能在 Expo Go 跑。

## 二、背景：為什麼現在是 WebView

從 git 紀錄整理（不是 Agent 的判斷）：
- 2026-10-31 `f98f9af`：清單整塊改成用網頁版 easynote 的程式畫，理由是打字、換行、滑動、拖曳、鍵盤「跟網頁版一樣」。
- 在那之前 `58d0d77`：原生版的系統鍵盤工具列在 Typeless 這類輸入法不會出現，只好自己畫一條。

也就是說，原生版是多米實測過、不滿意才換掉的。

## 三、兩個候選的已知差別（從程式看得出來的事實）

| 項目 | WebView（現在） | 原生元件 |
|---|---|---|
| 系統字級放大（動態字級） | 不跟：網頁裡字級寫死 17px（審查 #7） | 可以跟 |
| VoiceOver 劃掉、刪除 | 沒有替代路徑（審查 #8） | 可以加自訂動作 |
| 鍵盤工具列 | 用 Safari 那條「︿ ﹀ 完成」，Typeless 下會不會出現：**待真機** | 系統工具列在 Typeless 不出現（多米之前實測過） |
| 打字、滑動手感 | 多米選它的原因 | 多米之前不滿意 |
| 跟網頁版同一份程式 | 是 | 否，兩邊要分開維護 |

「哪個手感比較好」這欄 Agent 不填，要靠下面的真機測試。

## 四、要量的東西（照同一份方法量兩個候選）

只有 WebView 版現在能測。原生版要先做出來才能比，所以建議**先只測 WebView 版**：如果它在下面幾項都過了，就不用花力氣做原生版。

| # | 測什麼 | 怎麼測 | 誰 |
|---|---|---|---|
| 1 | 核心任務做一遍順不順 | 真機上：冷啟動 → 進清單 → 新增一行 → 打一句 → 再新增一行 → 往右滑劃掉 → 往左滑刪除 → 復原 → 拖曳排序。記下哪一步卡、等、跳 | 多米 |
| 2 | 打字延遲 | 240fps 慢動作同時拍手指和螢幕，數「按下按鍵」到「字出現」幾格，每格約 4 毫秒 | 多米 |
| 3 | 舊機＋低電量 | 手邊最舊的 iPhone、開低電量模式，清單放 50 行，快速捲動、連續劃掉，看有沒有掉幀 | 多米借舊機 |
| 4 | 最大字級 | 設定 → 輔助使用 → 放大文字開到最大，看清單頁的字有沒有變大 | 多米 |
| 5 | VoiceOver | 打開 VoiceOver，閉眼試：新增一行、打字、劃掉一行。記下卡在哪 | 多米 |
| 6 | 輸入法 | 用 Typeless（或你平常用的輸入法）打字，鍵盤上方有沒有「完成」可以收鍵盤 | 多米 |

結果寫進 `手感測試紀錄.md`。
