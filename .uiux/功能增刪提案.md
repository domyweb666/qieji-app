## 結論

1.0 不缺大功能。要先處理的是三件小事：

1. **兩個說法跟實際做法對不上**：「清掉劃掉的行」沒有進最近刪除（F1）；送審文案說貼好幾行會自動拆開，11/03 起已經不拆了（F2）
2. **切換清單改版後，「新的一張」不在切換清單裡**：要先猜到它在「管理所有清單」裡面（F3）
3. **使用者沒有地方回報問題**：茄記不收資料、不連網，能知道哪裡壞掉的只有評論和來信（A1 關於茄記）

值得加的新功能都在**入口**，讓「想到 → 記下」更短：圖示長按（A2）、記一行小工具（A5）、從別的 app 分享進來（A3）、Siri（A6）。

該刪的只有「上下順序反轉」（D1）。目錄那套主畫面系統不刪，但凍結，不再往裡面加東西（D2）。

最先要定的是**定位（決定 0）**：茄記是「待辦」還是「隨手記」。這一題決定別人拿什麼標準嫌它少了功能。

## 一、判斷用的四個問題

2-2「加功能之前過三道問題」，再加茄記自己的第四題：

1. **它幫「記」嗎？** 讓「想到 → 記下」變短，或讓人更敢忘掉（存好了、找得回來、不會不見）
2. **多少人用、多常用？**
3. **它讓哪個畫面多一個東西要理解？** 碰到核心迴圈的，寫「記多了幾層」（lessons 2026-11-01：記每被多包一層，真機就體感差）
4. **它會不會變成壓力？** 茄記跟提醒事項、備忘錄的差別就在這

功能分層（2-2）：

| 層 | 茄記裡是誰 | 放哪 |
|---|---|---|
| 核心（每個人、每次） | 紙、右下 ＋、輸入框 | 直接在畫面上 |
| 偶爾（部分人、有時候） | 切換清單、⋯ 選單、長按選單、目錄、搜尋 | 一步可達 |
| 很少（少數人、很少） | 最近刪除、關於茄記（新） | 再深一層 |

## 三、決定 0：茄記是「待辦」還是「隨手記」？

> ✅ 多米 2026-11-04 定：**隨手記**（原話「是隨手記」）。下面留著當時的依據。關鍵字留一個「待辦」，多米 2026-11-04 看過文案草稿後定。

現在兩種說法都有：

| 在哪 | 怎麼說 |
|---|---|
| `01` 核心動作卡 | 隨時記零碎想法、大部分放著、核心動詞＝記、差別＝沒有壓力 |
| README 第一句 | 「iPhone 待辦清單 app」 |
| 送審關鍵字 | 待辦、待辦事項、todo、checklist |
| 送審描述 | 小工具「看一眼就知道今天還剩什麼」（「還剩」是在算你欠多少） |

**為什麼要先定**（2-1）：人會帶著同類 app 的經驗進來。從「待辦」找到茄記的人，腦中的樣子是提醒事項，會找提醒、到期日、重複。這些全在不做清單裡，評論就會寫「連提醒都沒有」。同樣的不做清單，講成「茄記不會催你」是優點，被當成待辦 app 就變成缺點。

| 方案 | 做什麼 | 代價 |
|---|---|---|
| **甲 隨手記為主（推薦）** | 副標題、描述第一段直接講不做的事（沒有提醒、沒有到期日、沒有紅點），當成賣點；關鍵字留「待辦」吃搜尋量，但進來的人第一眼就知道這裡不催人 | 文案要重寫一段；會放掉一部分想要提醒功能的人（本來就留不住） |
| 乙 純待辦 | 文案不動 | 不做清單會一直被當成缺功能，加功能的壓力會從評論來 |
| 丙 純隨手記 | 關鍵字拿掉待辦、todo | 搜尋曝光變少 |

**最便宜的驗法**（3-1 一句話測試，不用寫程式）：給 3～5 個沒聽過茄記的人看副標題＋第一張截圖，問「這是什麼時候用的？」。合格答案的樣子：「喔，就是想到東西先丟著的時候用的」。文案由多米寫（銷售頁那套），這份不代擬。

## 四、該修的（送審前做，都小）

### F1 清掉劃掉的行，要進最近刪除

| 項目 | 內容 |
|---|---|
| 現況 | ⋯ →「清掉劃掉的行」只有 3.5 秒的「復原」，沒放進最近刪除（`Paper.tsx` 只改 `items`，沒呼叫 `binItem`）。單行刪除有進。README 與送審描述都寫「刪掉的紙和行都先進最近刪除，30 天內可以還原」 |
| 會怎樣 | 手滑按到、或 3.5 秒內沒看到 toast，十幾行劃掉的就永遠不見（2-8 傷信任） |
| 改法 | 跟單行刪除走同一條：清掉的行進最近刪除「刪掉的行」那一段；toast 改「已把 N 行移到最近刪除・復原」 |
| 不做 | 不加確認框（🔴 重複出現的確認框會被習慣化，2-8）。有最近刪除就夠 |
| 記多了幾層 | 0（不碰記） |
| 成本 | 小；加一條測試（清掉後 `bin` 多 N 行、還原回原本那張） |

### F2 貼上好幾行：說法要跟做法一致

現況：11/03 起（`be309b9`）一則裡按 Return 是換行、貼上整段留在同一則；右下 ＋ 的輸入框貼上好幾行，也是整段變成一行。README 和送審描述還寫「從備忘錄複製好幾行貼進來，會自動拆成好幾行」。`splitPasted` 現在只剩測試在用。

新使用者第一天常會把舊清單從備忘錄搬進來，這句話剛好是他會去試的。

| 方案 | 做什麼 | 代價 |
|---|---|---|
| **甲 輸入框貼上時給一顆「拆開」（推薦）** | 只在右下 ＋ 的輸入框裡：貼上的字有換行時，框上面冒一顆小膠囊「拆成 5 行」。不按＝整段一行（照 11/03 的決定）；按了＝拆成 5 行，照原本順序放到最上面，toast「已記下 5 行・復原」。在行裡改字時貼上，維持整段 | 多一顆只在貼上時出現的膠囊；要寫一點程式 |
| 乙 不拆 | 文案拿掉那句 | 搬家要一行一行貼 |
| 丙 輸入框貼上一律拆 | 回到 K5，只在輸入框 | 想貼一整段的人會被拆散，跟 11/03 的決定衝突 |

記多了幾層：甲、乙、丙都是 0（甲不按就跟現在一樣）。

### F3 切換清單最上面加「＋ 新的一張」

| 項目 | 內容 |
|---|---|
| 現況 | 想開一張新的：點清單名 → 切換清單裡沒有 → 要猜到在「管理所有清單」裡 → 目錄 → 搜尋框旁的 ＋。11/04 改版前，點清單名就到目錄，第一眼就看得到 |
| 問題在哪 | 不是步數多，是第二步看不出下一步（3-2「每一步看得出下一步」；🔴 三次點擊法則不成立，重點是每一步清楚） |
| 改法 | 切換清單最上面一列「＋ 新的一張」，茄紫字（iOS 選單把「新增…」放最上面是慣例）。點了：面板收起 → 新的一張黃色紙 → 輸入框升起（照 `02` 的 T2） |
| 讀屏 | 「新的一張」，按鈕 |
| 記多了幾層 | 0；T2 回到改版前的長度 |
| 成本 | 小 |

### F4 搜尋框「搜尋筆記」改成「搜尋」

詞彙表第 1 條把「筆記」拿掉了，整張叫「清單」、一條叫「行」。現在的搜尋同時找清單名和每一行，照 iOS 慣例只寫「搜尋」最不會錯。搬行模式維持「搜尋清單」。

## 五、該刪的

### D1 刪掉「上下順序反轉」（❓）

- 很少用（2-2 第三層）
- 它是一次性的翻轉，不是排序方式。翻完之後新記的還是插在最上面，順序變成一半新到舊、一半舊到新，看不出規則
- ⋯ 選單的「清單」那組會只剩有劃掉的行才出現的兩項，選單短一點

多米如果有在用（例如想照時間順序從頭讀），就留著。

### D2 目錄的主畫面系統：不刪，凍結

老實講：這是整個 app 最大的複雜度（`DirPanel.tsx` 1525 行、十幾輪真機修），但它的使用頻率是「偶爾～很少」。清單不多的人，多頁、資料夾、空位都碰不到。

不刪的理由：已經做完、多米真機驗過大半；對只有幾張清單的人，它就是一頁方磚，不擋路（2-2 失效邊界 2：選項多本身不是問題，被迫做決定才是）。

凍結＝1.x 不在目錄加任何東西。上架後評論裡如果常出現「找不到」「資料夾怎麼開」，再回審查線。

### D3 程式裡看不到的遺留（使用者看不到，下一版前清）

收成（`Garden`）、四種排序（`SortKey` 與排序字）、匯出匯入（`exportJSON`、`importBackup`、`backupName`）、貼上拆行（`splitPasted`，F2 選乙的話）、網頁版的 `type`／`body`。完工驗收書已經寫了「第二版前跑一次 vibe-integrate」，照那個做。

| 邊界 | 那張滿 1000 行：記下變灰，下面寫「這張滿了，換一張」；iCloud 沒開照樣存在手機；分享的是圖片：分享表上不出現茄記（只收文字和網址） |
| 記多了幾層 | 五個動作變兩個（分享 → 記下） |
| 成本 | 中～大。正規做法：`@bacons/apple-targets` 的分享延伸（Swift 畫面）＋ App Group 裡一個「收件匣」檔，茄記回到前景時把收件匣併進紙。**不用** Expo 自己的 `expo-sharing` 分享延伸：SDK 58 文件標實驗功能，做法是打開茄記本體，文件寫明 Apple 不正式支援、之後的 iOS 可能失效 |
| 不可逆 | 收件匣併進紙之後會上 iCloud，照慣例先問要不要把這片排在後面、等真機 |
| ❓ | 預設放哪張：**上次那張（推薦，跟控制中心、小工具同一個規則）**／固定一張「收件匣」（多一個概念要懂） |

#### A4 行裡的網址能打開

| 項目 | 內容 |
|---|---|
| 為什麼 | A3 會帶進很多網址。現在一行裡的網址只是字，想打開要：點進去改字 → 全選 → 複製 → 去 Safari |
| 第一步（推薦先做） | 有網址的行，網址畫成茄紫字；長按選單多一項「打開連結」（只有那行有網址才出現）。「點一下改字」完全不動，沒有手勢衝突 |
| 第二步（❓ 之後） | 點網址本身就打開（像備忘錄）。代價：同一行「點字＝改字、點網址＝開連結」，同一個點擊兩個意思。lessons 記過兩次「同一塊、同一方向兩個意思」，要先真機試，網址短的時候很容易點錯 |
| 記多了幾層 | 0 |
| 成本 | 第一步小 |

#### A5 小工具改成「記」優先

| 項目 | 內容 |
|---|---|
| 為什麼 | 核心動詞是記，但現在的小工具只能看，點了只打開 app。而且「上次那張」會跟著你最後看的那張一直換，放在主畫面上的內容不穩定 |
| 1. 新的「記一行」小工具 | 小尺寸：整塊一顆大 ＋ 和「記一行」。鎖定畫面圓形：一顆 ＋。點了＝`qieji://new`（跟控制中心同一條） |
| 2. 紙小工具可以選哪一張 | 長按小工具 → 編輯小工具 → 清單：上次那張（預設）／旅行／…。那張被刪了：顯示「這張已刪除」，點了打開茄記 |
| 3. 中、大尺寸右上角一顆 ＋ | 點 ＋＝記一行；點其他地方＝打開那張 |
| 記多了幾層 | 從鎖定畫面：解鎖 → 找圖示 → 按 ＋，變成按 ＋（Face ID 解鎖後直接是輸入框） |
| 成本 | 1 小；2 中（清單名要由 app 推給小工具）；3 小～中。都要重建開發版 |
| 已查證 | SDK 58 的 `expo-widgets`／`@expo/ui`：有 `widgetURL`、支援 `accessoryCircular`、支援 iOS 17 以上的可設定小工具（`ios.configuration`，清單名用 `setConfigurationParameterEnum` 動態給）。小工具裡的 `Link`（第 3 件）文件沒寫，要真機試 |
| 跟控制中心的關係 | 控制中心按鈕放的是鎖定畫面最下面那兩顆的位置；圓形小工具放的是時間下面那排。兩個位置不同，不衝突 |
| 不做 | 在小工具上直接劃掉。iOS 17 能互動，但 `expo-widgets` 的互動只改小工具自己的資料，茄記沒開時接不到，小工具和紙會對不上（傷信任） |

#### A6 Siri 與捷徑「用茄記記一行」

| 項目 | 內容 |
|---|---|
| 為什麼 | 手不空的時候（走路、煮飯、拿著東西）也能記。控制中心那顆的 `NewLineIntent` 本來就是 App Intent，只差一組片語，就會自己出現在 Spotlight、捷徑 app、Siri |
| 第一步（小） | 加片語「用茄記記一行」→ 打開茄記、輸入框升起（跟控制中心一樣） |
| 第二步（中） | 帶內容：「用茄記記：買牛奶」→ 直接記進上次那張，不打開 app；Siri 回「記好了，在「X」最上面」。資料走 A3 那個收件匣 |
| 記多了幾層 | 少兩層 |
| 會過時 | Siri 中文片語、App Intents 每年 WWDC 都在改，實作前重查；要真機用中文 Siri 試 |

#### A7 評分提示（上架後）

| 項目 | 內容 |
|---|---|
| 為什麼 | 個人開發沒有行銷預算，評分是別人決定要不要裝的少數線索之一 |
| 時機（2-9 高峰之後） | **不在記的時候跳**：記完的結尾是放下手機，多包一層就體感差。茄記的高峰是「劃掉」（有做到的那一刻）。條件例：裝了 7 天以上、累計劃掉 10 行以上，在劃掉的動畫結束、手指離開之後，跳一次系統評分框 |
| 規則 | 只用系統的評分框（`expo-store-review`）。次數上限由系統管（會過時，實作前查） |
| ❓ | 做不做、條件怎麼定 |
